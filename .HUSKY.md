# Husky Setup - Pre-commit Hooks

Este proyecto está configurado con **Husky** para ejecutar validaciones automáticas antes de hacer un commit.

## 🚀 Instalación

Las dependencias se instalan automáticamente con:
```bash
npm install
```

El script `prepare` en `package.json` inicializa Husky automáticamente.

## 🔍 Validaciones de Pre-commit

Antes de hacer commit, Husky ejecuta:

### 1. **TypeScript Check** (`npm run typecheck`)
   - Valida que no haya errores de tipos en TypeScript
   - Se ejecuta en todos los archivos `.ts` y `.tsx` staged
   - Si hay errores, el commit se cancela

### 2. **Jest Tests** (Opcional)
   - Puedes agregar tests ejecutando: `npm test`
   - Tests NO se ejecutan automáticamente en pre-commit (por rendimiento)
   - Ejecuta manualmente: `npm run test`

## 📝 Configuración

### `.husky/pre-commit`
Script que se ejecuta antes de cada commit. Usa **lint-staged** para:
- Ejecutar solo en archivos modificados (más rápido)
- Revertir cambios automáticamente si falla

### `.lintstagedrc.json`
Define qué validaciones ejecutar según el tipo de archivo:
```json
{
  "*.{ts,tsx,js,jsx}": ["npm run typecheck"]
}
```

## ✅ Flujo de uso

### Commit normal (con validaciones)
```bash
git add src/file.ts
git commit -m "feat: nueva feature"
```

Si hay errores de TypeScript → commit se rechaza.

### Commit sin validaciones (fuerza)
Si necesitas saltarte las validaciones temporalmente:
```bash
git commit -m "mensaje" --no-verify
```

⚠️ **No recomendado** en repositorios compartidos.

## 🛠 Comandos útiles

```bash
# Instalar Husky desde cero (si se borra .husky/)
npm run husky -- install

# Ver el pre-commit hook
cat .husky/pre-commit

# Desactivar temporalmente Husky
npm run husky -- uninstall

# Reactivar Husky
npm run prepare
```

## 🐛 Troubleshooting

### "husky is not installed"
```bash
npm install
```

### Pre-commit hook no se ejecuta
```bash
chmod +x .husky/pre-commit
npm run prepare
```

### TypeScript errors bloquean commit
Revisa: `npm run typecheck`

### Lint-staged reverting changes
Si ves "Reverting to original state" → hay errores en los validadores.
Chequea: `npm run typecheck` directamente.
